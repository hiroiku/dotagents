# gate

testing の規則をすり抜けたコマンドを hook で止めるゲート。作業中に時間のかかる検査を全体へ回すコマンド、フォアグラウンドで待つだけのコマンド、待ち方を取り違えたコマンドを見つけ、理由と代わりの手を添えてエージェントへ差し戻す。[testing](../testing/README.md) モジュールと一緒に入れる。

規則を読ませる仕組みが先にあり、これは最後の保険である。止める前に、規則そのものがコマンドを選ぶ瞬間に効いていることを目指す。

## 何を止めるか

| 止めるもの | 見分け方 | 通すもの |
|---|---|---|
| 作業中の重い検査 | コマンドに検査の語(test、spec、check、lint、verify など)を含み、対象を絞る指定が無く、同じリポジトリーの同じ場所での直近の実行の中央値が 45 秒以上 | 初めて見る検査、記録が 1 回だけの検査、軽い検査、対象を絞った確認、`DOTAGENTS_VERIFY=final` を付けた検査 |
| 前回から何も変わっていない重い検査 | 重い検査で、HEAD もコミットしていない変更も、その検査を最後に実行したときと同じ | 軽い検査、前回から変更のある検査、git が状態を答えない場所、`DOTAGENTS_REPEAT=1` を付けた検査 |
| フォアグラウンドで待つだけのコマンド | 30 秒以上の sleep、`sleep infinity`、sleep を挟んで状態を確かめ続けるループ、合計 30 秒以上待つ回数の決まったループ(どちらも sleep の長さを問わない)、`tail -f`(`timeout` で包んだものを含む) | 短い sleep、起動を確かめるループ、合計の短い繰り返し、起動を確かめる `tail -f`、バックグラウンドの実行 |
| 対話を担当するセッションがフォアグラウンドで CI を待つコマンド | `gh run watch`、`gh pr checks --watch` | サブエージェントの実行、バックグラウンドの実行 |
| サブエージェントがバックグラウンドで始める検査 | Claude Code のサブエージェントからの呼び出しで、`run_in_background` を付けた検査 | 対話を担当するセッションの実行、検査でない処理(dev サーバーなど)、フォアグラウンドの検査 |

Claude Code は単独の長い sleep を本体で止めるので、sleep だけのコマンドの判定が効くのは主に Codex である。ループと `tail -f` の判定は両方で効く。`sh -c '…'`・`bash -c`・`zsh -c` の中身も同じように読む。sleep を止められたエージェントは、`timeout 540 tail -f /dev/null` や `bash -c` の中のループ、`for i in $(seq 1 280); do sleep 1; done` のような 1 秒刻みの繰り返しのように、形を変えて待とうとすることがあるからである。ループは sleep 1 回の長さではなく、待つ合計で判定する。

CI の完了を待つコマンドは、サブエージェントには正しい待ち方である。サブエージェントは、ターンを終えると親へ戻るので、バックグラウンドに回した物の完了を受け取れない。逆に、対話を担当するセッションがフォアグラウンドで待つと、そのあいだユーザーと会話できない。バックグラウンドへ回せば完了が通知で届く。同じ理由で、サブエージェントがバックグラウンドで始めた検査は、完了を受け取れずに出力の監視で待つことになるので、始める時点で止める。

対象を絞る指定として読むのは、パス、テスト名のような位置引数、名前で選ぶオプションの値(`-k`、`--filter=`、`-Dtest=` など)である。設定のオプションの値(`--project`、`--reporter` など)、数や真偽の値、設定ファイル、`.` や `./...` のような全体の指定は、絞り込みとして読まない。迷う指定は、止めない側に倒す。

## どの言語にも効く

ツールごとの規則を持たない。検査かどうかはコマンドに含まれる語で、重いかどうかは実測で見分けるので、テストランナーや型チェックの種類を問わない。語の一覧には、検査の語を名前に含まない代表的な型チェックと lint の名前(tsc、mypy、pyright、clippy)と、起動の確認に使う語(curl、ready、health など)も入っている。

初めて見る検査は通して時間を測り、記録が 2 回そろってから判定に使う。中央値は、記録が偶数個なら小さい側を取る。キャッシュの切れた 1 回や、権限の確認を待った 1 回だけで止めないためである。

実測は `~/.dotagents/cache/gate/<リポジトリーごとの識別子>/` に置く。同じリポジトリーの worktree は同じ記録を読む。同じコマンドでも、作業ツリーの最上位からの場所(`cd packages/api` の後など)が違えば別の検査として測る。記録の鍵は検査の部分だけで作るので、`git log --oneline -1 && make check` のように検査でないコマンドを前に付けても同じ検査として測る。検査を 2 つ並べたもの(`make lint && make test`)は、別の検査として測る。

記録の鍵からは、検査の中身を変えない指定も外す。起動の形(`npx`、`bunx`、`bun run`、`uv run`、`bundle exec`、`node_modules/.bin/` をパスで直接呼ぶ形など)と、出力の形・並列の度合い・最初の失敗で止めるかだけを変えるオプション(`--reporter`、`--pretty`、`--checkers`、`-j`、`--bail` など)、既定の設定の場所を明示しただけの指定(`-p tsconfig.json`)である。止められたエージェントは、こうした指定を付け替えて同じ全体の検査を実行し直すことがあり、鍵が変わると初めて見る検査として通ってしまう。対象の選び方を変える指定(`--project`、`--shard`、`-b`、`--incremental` など)は残す。かかる時間が違う別の検査だからである。

作業ツリーの状態は、HEAD と、コミットしていない変更(追跡していないファイルを含む)の名前・大きさ・更新時刻から作り、worktree ごとに覚える。並行する別の worktree の実行では上書きしない。読むのは重い検査のときだけである。軽い検査のたびに git を呼ぶと、その分だけ全体が遅くなる。内容を戻す変更や、gitignore したファイルの変更は、状態の違いとして読めないものがある。迷う場合は、止めない側に倒す。

## 止めたあと

差し戻しには、止めた理由と代わりの手が入る。重い検査なら、変更したファイルだけに絞るか、共有のブランチへ push する前の検査として `DOTAGENTS_VERIFY=final` を付けて実行し直す。型の検査のようにファイルで絞れない検査には、絞る代わりに増分で検査する指定を示す。絞れない検査に「変更したファイルだけ」と返すと、エージェントは言い換えてすり抜けるか、検査そのものをやめてしまう。前回から何も変わっていない検査なら、前回の結果をそのまま使う。同じ状態でも結果が変わりうる検査(ネットワークに依存する検査、不安定なテストの確認)だけ、`DOTAGENTS_REPEAT=1` を付けて実行し直す。待つだけのコマンドなら、処理そのものをフォアグラウンドで実行するか、完了の通知を受け取る。ユーザーと対話しているセッションには、ターンを終えるよう伝える。サブエージェントには、エージェントの完了を待つなら 1 つのメッセージでまとめてフォアグラウンドで起動するよう伝える。サブエージェントはターンを終えると親へ戻るので、バックグラウンドに回した物の完了を受け取れないからである。CI を待つコマンドを止められた対話のセッションには、バックグラウンドで実行するよう伝える。バックグラウンドの検査を止められたサブエージェントには、時間の上限を付けてフォアグラウンドで実行し、上限に収まらない全体の検査は push の前の検査に任せるよう伝える。

止めた検査は実行されないので、記録は更新されない。記録が新しくなるのは、`DOTAGENTS_VERIFY=final` を付けて実行したときである。

判定できない入力や記録の失敗では、何もせずに通す。ゲートの誤りで作業そのものを止めないためである。

## 配備

- Claude Code: plugin の `hooks/` に届き、`PreToolUse`・`PostToolUse`・`PostToolUseFailure` で動く。
- Codex: `codex/hooks.json` がマシンに 1 つの dotagents の Codex plugin に、実行ファイルが `.codex/dotagents/gate/` に届く。Codex の `/hooks` で信頼すると動く。信頼はマシンごとに 1 度で済み、プロジェクトの `.codex/hooks.json` には触れない。
- 実行には bun か node を使う。bun を優先するのは、Bash の呼び出しごとに起動するため、起動の速さが効くからである。
