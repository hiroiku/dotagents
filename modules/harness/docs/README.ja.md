[README](../../../docs/README.ja.md) が説明するのは仕組み — 正本 1 つを module へ切り分け、`agents-setup` がそれを `~/.claude` と各プロジェクトの `.claude/` へ install する — である。この文書が説明するのは、それと共に手に入る module である: 完全に動くハーネス一式であり、そこから出発して自分用に個人化するためのサンプルとして同梱されている。

## 判断するモデルのために書かれている

このハーネスは、規則よりも判断によく従う現世代のモデルのために作られている。指示は 1 つごとに二重のコストである: セッションの有限の注意を占有し、モデル自身の判断の方が優れているかもしれない場面でモデルを縛る。だから正本に記録するのは、有能なモデルが導出できない物だけである:

- **意見** — どれほど有能でも推測できない慣習: コミットのタイトルの付け方、コミットメッセージに決して入れない物
- **アンカー** — 成果物が満たすべき外部の正典: OWASP Top 10、WCAG 2.2 AA
- **境界** — 誰が何をしてよいか: 編集できないレビュアー

それ以外のすべて — どう探索するか、どこまで深く行くか、指摘がどんな形をとるか — はモデルに委ねる。失敗モードが実際に観測されたときに、それを防ぐ最小の指示を足す。前もって足す物は無い。較正のためのガイドは [prompting](../skills/prompting/SKILL.md) スキルに挙げられており、この正本のプロンプトを編集する前に読まれる。

## 配達の三つの形

- **遍在則**([AGENTS.md](../AGENTS.md))— 全セッションに注入され、全セッションの注意に課税するので、収めるのは、その瞬間をトリガーに任せられないわずか数行だけである: _実装や修正を終えたら、完了を報告する前に該当するレビュー系サブエージェントへ検証を委譲する。_ そして _コメントはそのコードの意図を説明する — 経緯も ADR も、将来への備えも書かない。_
- **瞬間則**([skills/](../skills/))— その瞬間が来たときだけ読まれる: [git](../skills/git/SKILL.md) はコミット時に、[testing](../skills/testing/SKILL.md) はテストを書くときに、[prompting](../skills/prompting/SKILL.md) はプロンプト編集時に。ここに書く詳細は、他のどの瞬間にもコストを課さない。
- **役割**([agents/](../agents/))— 自分専用の context と制限されたツールセットを持つサブエージェント。役割がしてはならないことは、覚えておくべき 1 文ではなく、与えられていないツールによって強制される。

Claude Code はこの 3 つを 1 つの plugin として受け取るので、スキルは `/dotagents:git`、エージェントは `dotagents:review` として呼び出される。plugin を持たない Codex は、スキルを `dotagents-git` のような名前で受け取る。

## レビュー — クリーンな context が、欠けている物を狩る

AI エージェント特有の失敗モードは、終わっていないのに「完了しました!」と言うことである — 嘘ではなく欠落: 書いた物しか持たない context には、書かなかった物が見えない。だから検証は、context がクリーンなレビューエージェントへ渡す。彼らが受け取るのは、要件、対象の見つけ方、動かし方であり — 実装者の自己報告は決して渡さない。

[review](../agents/review.md) は 2 つのパスを順に実行する:

1. **存在** — 各要件を起点に、それを満たす実装を探す。欠落は差分の中には見えないので、走査は差分から外へではなく、要件からコードへ向かって行う。
2. **正しさ** — 見つかった物が正しく作られているかを検分する。

レビュアーは読み、実行する。編集はしない。ツールセットの全体は `Read, Glob, Grep, Bash` である。

## チェックリストではなく、要件アンカー

[security](../agents/security.md) は [OWASP Top 10](https://owasp.org/Top10/) に照らして検証し、[accessibility](../agents/accessibility.md) は [WCAG 2.2](https://www.w3.org/TR/WCAG22/) の適合レベル AA に照らして検証する。それぞれ自分の正典を名指しし、そこで止まる: チェックリストの写しは持たず(写しは正典が動くにつれて古びる)、その上に独自基準も足さない(列挙は判断を列挙者の想像力に縛る)。どのカテゴリがどう当てはまるかは、目の前のコードに照らして判断される。

## Git — モデルには推測できない慣習

[git](../skills/git/SKILL.md) が意見の全体を数行で収める: コミットタイトルは業務にとって何が変わったかを言い、ファイル名や内部識別子は決して書かない。コミットメッセージや PR に AI の帰属表示は入れない。統合の既定は squash。上流への追従は merge ではなく rebase で行う。

## テスト — 望ましい性質、プロンプトサイズで

[testing](../skills/testing/SKILL.md) は [Test Desiderata](https://testdesiderata.com/) をプロンプトとして仕立て直した物である: 良いテストの 12 の望ましい性質 — 何よりもまず、振る舞いに敏感で構造に鈍感、つまりテストが落ちるのは約束された振る舞いが破れたときだけ — を、性質どうしは互いにトレードオフであり、その配合は意図して選ばれるという正典自身の枠組みごと収める。この module の他のどのアンカーとも同じく、正典を名指しし、そこで止まる。

この module は外部要件を宣言しない: プロンプトと役割の定義だけであり、Claude Code か Codex が動く場所ならどこでも動く。
