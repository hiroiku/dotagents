# testing

テストの設計と検証の進め方を扱う共有ルール。

[AGENTS.md](AGENTS.md) は常設ルールとして、作業中は変更したファイルだけを検査すること、全体の検査は push の前に 1 回だけ実行し、そのあとは CI に任せること、待ち方を配る。検証はほぼすべての作業で行い、その判断はコマンドを打つ瞬間に要るので、スキルの呼び出しを待たずに読み込む。

[skills/testing/SKILL.md](skills/testing/SKILL.md) は、[Test Desiderata](https://testdesiderata.com/) に基づくテストの設計、作業中に範囲を絞る方法、push の前と統合後の全体の検査を示す。テストを書くときと、絞り方が分からないときに読む。

振る舞いを検証し、構造だけの変更には反応しないテストを目指す。性質の間にトレードオフがあるときは、対象に必要な信頼性から判断する。

使うテストランナー、ファイル配置、カバレッジの数値、検査コマンドは、プロジェクトの設定ファイルと workflow が正本であり、指示には写さない。このモジュールはどの言語・どのツールにも当てはまる技法だけを持ち、各ツールの具体的な指定はモデルの知識と、そのファイルを読むことに任せる。

規則をすり抜けた重い検査と待つだけのコマンドは、[gate](../gate/README.md) モジュールの hook が止める。
