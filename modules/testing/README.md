# testing

テストの設計と検証の進め方を扱う共有ルール。

[AGENTS.md](AGENTS.md) は常設ルールとして、作業中は変更したファイルとそれに依存するテストだけを検査すること、共有のブランチへ push する前に統合する側が 1 回だけ検査すること、待ち方を配る。CI は手元より資源が少なく、実行ごとにお金もかかるので、CI で落ちないよう手元で確かめてから出す。push の前の検査は、製品グレードのブランチや環境(push やマージで staging や production へ配備されるもの)へ入る前だけ CI の必須の検査を通しで実行し、それ以外は取り込んだ差分に関係する検査にする。大きなプロジェクトでは、テストが作業時間のほとんどを占めないようにするためである。検証はほぼすべての作業で行い、その判断はコマンドを打つ瞬間に要るので、スキルの呼び出しを待たずに読み込む。

[skills/testing/SKILL.md](skills/testing/SKILL.md) は、[Test Desiderata](https://testdesiderata.com/) に基づくテストの設計、作業中に範囲を絞る方法、push の前の検査(通しにするときと、差分に関係する検査の作り方)を示す。テストを書くときと、絞り方が分からないときに読む。

振る舞いを検証し、構造だけの変更には反応しないテストを目指す。性質の間にトレードオフがあるときは、対象に必要な信頼性から判断する。

使うテストランナー、ファイル配置、カバレッジの数値、検査コマンドは、プロジェクトの設定ファイルと workflow が正本であり、指示には写さない。このモジュールはどの言語・どのツールにも当てはまる技法だけを持ち、各ツールの具体的な指定はモデルの知識と、そのファイルを読むことに任せる。

規則をすり抜けた重い検査と待つだけのコマンドは、[gate](../gate/README.md) モジュールの hook が止める。
