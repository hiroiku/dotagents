# testing

テストの設計と検証の進め方を扱う共有ルール。

[AGENTS.md](AGENTS.md) は常設ルールとして、作業中は変更したファイルとそれに依存するテストだけを検査すること、共有のブランチへ push する前に統合する側が 1 回だけ検査すること、待ち方を配る。CI は手元より資源が少なく、実行ごとにお金もかかるので、CI で落ちないよう手元で確かめてから出す。push の前の検査は、製品グレードのブランチや環境(push やマージで staging や production へ配備されるもの)へ入る前だけ CI の必須の検査を通しで実行し、それ以外は取り込んだ差分に関係する検査にする。大きなプロジェクトでは、テストが作業時間のほとんどを占めないようにするためである。検証はほぼすべての作業で行い、その判断はコマンドを打つ瞬間に要るので、スキルの呼び出しを待たずに読み込む。

型の検査のようにファイルで絞れない検査は、作業中は増分で検査する指定で実行する。「変更したファイルだけ」という規則は絞れない検査には当てはめようが無く、それだけを書いていたころは、毎回全体を回すか、検査そのものをやめるかに分かれていた。

差分に関係する検査でも、ファイルごとに掛かるカバレッジの閾値は、差分のファイルについて確かめる。CI はブランチによってテストやカバレッジを省いていることがあり、そこを「CI で確かめる」に任せると、未達が製品グレードへ入る前の通しの検査まで見つからない。見つかった時点では未達が積み上がっていて、直し終えるまでリリースが止まる。ファイルごとの閾値は、そのファイルに依存するテストだけで判定できるので、差分の検査に足しても通しと同じ判定になる。

依存をたどってテストを選ぶ機能には、ソースのファイルだけを渡す。ツールによっては、依存の定義や設定のファイルを渡しただけで、すべてのテストを選ぶ。差分をそのまま渡すと、依存の版を上げたコミットや script を足したコミットのたびに、通しの検査と同じ時間がかかる。

待ち方は、フォアグラウンドで時間の上限を付けるのを基本にする。ただし Claude Code は、バックグラウンドで動くサブエージェントのフォアグラウンドのコマンドを 180 秒で本体がバックグラウンドへ移すことがある。移されたら、出力のファイルに終わりの印が出るまで、175 秒以内の上限で待つことを繰り返す。この形なら、やりとりは検査の長さを 3 分で割った回数で済む。出力ののぞき直しや決めた時間の待ちは、終わった後も待ち過ごすか、やりとりを重ねる。成功すると何も出さない検査(型の検査など)は、終わりが出力に出ないので、`; echo "exit=$?"` で印を出しておく。

[skills/testing/SKILL.md](skills/testing/SKILL.md) は、[Test Desiderata](https://testdesiderata.com/) に基づくテストの設計、作業中に範囲を絞る方法、push の前の検査(通しにするときと、差分に関係する検査の作り方)を示す。テストを書くときと、絞り方が分からないときに読む。

振る舞いを検証し、構造だけの変更には反応しないテストを目指す。性質の間にトレードオフがあるときは、対象に必要な信頼性から判断する。

アクセシビリティーの要件のうち、操作のあとのフォーカスの行き先、結果や誤りの通知、アクセシブルな名前は、振る舞いとしてコンポーネントのテストで確かめる。以前は「アクセシビリティーのテストは作らない」としていた。その決まりのもとで作った 2 つのプロジェクトには、フォーカスや通知を確かめるテストが 1 つも無く、確かめる場所がレビュアーだけになった。アクセシビリティーのレビュアーは、時間の 8 割前後を、アプリを動かすことと、ブラウザーを操作するスクリプトを書いて実行することに使い、最初のレビュー 20 件のうち 17 件で指摘を出し、サブエージェントの時間の 16〜17% を占めた。フォーカスと通知を確かめるテストファイルが 100 近くあるプロジェクトでは、同じレビュアーが既存のテストを読んで実行するだけで済み、1.5% だった。片方のプロジェクトの指摘 40 件のうち 26 件は、フォーカスが失われる、通知が伝わらない、名前に見える文字が無い、のどれかで、DOM で確かめられる。コントラストや画面の幅ごとの配置は描画しないと分からないので、テストにせずレビューに残す。見た目のテストを作らないのは変わらない。

使うテストランナー、ファイル配置、カバレッジの数値、検査コマンドは、プロジェクトの設定ファイルと workflow が正本であり、指示には写さない。このモジュールはどの言語・どのツールにも当てはまる技法だけを持ち、各ツールの具体的な指定はモデルの知識と、そのファイルを読むことに任せる。

規則をすり抜けた重い検査と待つだけのコマンドは、[gate](../gate/README.md) モジュールの hook が止める。
