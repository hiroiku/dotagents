# testing

テストの設計と検証の進め方を扱う共有ルール。

[AGENTS.md](AGENTS.md) は常設ルールとして、作業中の確認を変更に関係する範囲に絞ること、重い検査を仕上げの検査として変更が仕上がってから実行すること、待ち方を配る。検証はほぼすべての作業で行い、その判断はコマンドを打つ瞬間に要るので、スキルの呼び出しを待たずに読み込む。

[skills/testing/SKILL.md](skills/testing/SKILL.md) は、[Test Desiderata](https://testdesiderata.com/) に基づくテストの設計、作業中に範囲を絞る方法、仕上げと統合後の検査を示す。テストを書くときと、絞り方が分からないときに読む。

振る舞いを検証し、構造だけの変更には反応しないテストを目指す。性質の間にトレードオフがあるときは、対象に必要な信頼性から判断する。

使うテストランナー、ファイル配置、カバレッジの数値、検査コマンドはプロジェクト側に置く。このモジュールはどの言語・どのツールにも当てはまる技法だけを持ち、各ツールの具体的な指定はモデルの知識とプロジェクトの指示に任せる。

規則をすり抜けた重い検査と待つだけのコマンドは、[gate](../gate/README.md) モジュールの hook が止める。
