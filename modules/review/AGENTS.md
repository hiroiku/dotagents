## レビュー

実装や修正を終えたら、完了を報告する前に、該当するレビューエージェントに検証を任せる。依頼に書く実行方法は、要件を満たしていないことを示せるテストや操作に絞ったコマンドにする。

- レビューは、実装した worktree で、報告された HEAD のコミットに対して行う。レビューのために worktree やブランチを作らない。レビューのあいだ、実装する側はその worktree を変更しない。
- ファイルを一時的に書き換えて確かめること(壊して落ちるかを見る、変更前のコードに戻して比べる)は、その worktree で動くレビュアーが 1 体だけのときに、依頼に書いて許す。並行するレビュアーがいるときに書き換えると、ほかのレビュアーの実行が書き換えた状態を読む。
- レビューから戻ったら、HEAD がレビューの前と同じで、コミットしていない変更が無いことを確かめる。
- 直すのは、レビュアーが完了を妨げると示した指摘だけにする。改善の提案は直さずに報告に載せ、判断を依頼元に任せる。
- 指摘の修正は、実装したエージェントに続けて依頼する。再レビューは、同じレビュアーに続けて依頼し(Claude Code では SendMessage)、修正のコミットを渡して、その指摘が解消されたかと修正の差分だけを確かめてもらう。新しいレビュアーは前回の指摘を知らずに初めから読み直し、新しい指摘を出し続けるので、往復が終わらない。
- 再レビューは 2 回までにする。それでも完了を妨げる指摘が残るなら、それ以上直さずに、残った指摘と食い違っている点を依頼元(対話を担当するセッションならユーザー)へ返す。直しても指摘が残り続けるのは、実装より要件や設計の食い違いであることが多い。
