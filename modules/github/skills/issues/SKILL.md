# GitHub

- AI の署名(`Generated with Claude Code`、`Co-Authored-By: Claude` など)とセッションの URL(`claude.ai/code/session_...`)を、コミットメッセージ、PR、issue の本文とコメントに入れない。

## GitHub Issues

- 1 つの issue は、マージした時点で動作する範囲にする。
- それだけでは完結しない大きさなら epic にして、中身を sub-issue に分ける。sub-issue は単体でマージできなくてよい。
- 個別に管理する必要があるものは sub-issue にする。管理する必要のない手順は本文に書く。
- 作成したら、タイプ、ラベル、マイルストーン、担当者、親子関係、依存関係のうち該当するものを設定する。値は、その organization とリポジトリーで既に使われているものから選ぶ。
- どのリポジトリーでも同じ意味になる区別はタイプ、そのリポジトリーでしか意味を持たない区別はラベルにする。新しく作るのは、既にあるどれでも絞り込めないときだけにする。
- 依存関係は親子関係とは別のもので、別の親、別のマイルストーン、別のリポジトリーの issue にも設定できる。検索では絞り込めないので、実際に見る人がいるときだけ設定する。
- 分かったことはコメントに書く。判明した原因、試して採用しなかった方法、途中で見つかった制約。
- クローズするときは、選べる理由のうち実際に起きたことに合うものを選ぶ。完了として集計される理由と、中止の記録として残る理由は別のものである。
- 重複した issue は、残すほうを参照してクローズする。

## GitHub Projects

- 着手したら、作業を始める前にステータスを進行中に変える。
- 状況が変わったら、その時点の状況に最も近いステータスに変える。
- 作業が進んだら、その時点でステータスを更新する。
- フィールドで表せる情報は、本文ではなくフィールドに設定する。

## ブランチ

- worktree を `.worktrees/issue-{id}` に作り、`issues/issue#{id}` という名前のブランチを作って、そこで作業する。
- sub-issue は親 issue のブランチにマージする。統合先のブランチにマージするのは親のブランチだけにする。
- sub-issue がすべてマージされたら、親 issue をクローズする。
- マージが完了したら、worktree とブランチを削除する。

## PR

- 作成したらすぐ、対応する issue にリンクする(`addCloseIssueReferences`)。base がどのブランチでも、issue の Linked pull requests に表示される。
- リンクに本文の `Closes #123` は使わない。これは base がデフォルトブランチのときしか解釈されない。
- issue にリンクしたブランチから PR を作っても、リンクされない。ドキュメントには自動でリンクされると書かれているが、実際には表示されない。
- 変更の説明は PR に書き、問題そのものは issue に残す。
- CI の完了は `gh run watch <run-id> --exit-status` か `gh pr checks <pr-number> --watch` で待つ。
