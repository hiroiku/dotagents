## issue を閉じる時期

- issue は、その変更がすべて取り込み先に入ったときに閉じる。取り込み先は、sub-issue なら親 issue のブランチ、それ以外は統合先である。閉じた issue は取り込み先に入ったことを表し、本番に出たかはマイルストーンと版の tag で表す。
- 統合する側は、issue の最後の区切りを取り込む squash のコミットの本文に `Closes #<番号>` を書く。取り込み先がデフォルトブランチなら、push や PR のマージで GitHub が完了として閉じる。デフォルトブランチでなければ自動では閉じないので、取り込んで push したあとに完了として閉じる。
- 一部の区切りだけが入った issue は開いたままにし、入ったコミットと残りを issue のコメントに書く。開いている issue を見れば、まだ取り込み先に入っていない作業が分かるようにするためである。
