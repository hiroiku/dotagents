# issue を棚卸しする

開いている issue は、閉じる数より増える数が上回ると、どれがまだ有効かが読めなくなる。1 件ずつ方針を決め、利用者の確認は 1 回にまとめて反映する。

1. 開いている issue を、古い順に並べる。
2. 1 件ごとに、やる(次のバッチに含める)、やらない(理由を付けて閉じる)、保留(順番を決めずに残す)のどれかを付ける。重複と、すでに修正されているものは、やらないに分類する。重複は、残すほうを参照して閉じる。
3. やるものは、書かれた修正方針が共通ルールの設計の基準に沿っているかを検証し直す。古い issue は、いまの基準に沿っていないことがある。
4. 1 つの表にして利用者に示し、1 回の確認で反映する。閉じる理由は、実際に起きたことに合うものを選ぶ。
