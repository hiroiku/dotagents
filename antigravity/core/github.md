### issue

- 1 つの issue は、マージした時点で動作する範囲にする。タイプ、ラベル、マイルストーン、担当者は、そのリポジトリーで使われている値から選ぶ。マイルストーンの名前は、プロジェクトに決まりが無ければ、リリースの tag と同じにする。Projects を使っているリポジトリーでは、着手したらステータスを進める。
- 本文は、それだけ読めばいまの状態が分かる要約に保ち、状態が変わるたびに書き直す。書くのは、いまの状態、決めたこと(日と人)、判断を求めていること(選択肢、おすすめ、トレードオフ)である。コメントは時系列の記録にし、書き直さない。issue とマイルストーンに、見込みから導いた期日や着手予定は書かない。利用者やプロジェクトが期日を決めたときは、それを書く。
- issue は、変更がすべてマージ先に入ったときに閉じる。デフォルトブランチ以外へのマージでは `Closes` が効かないので、push のあとに自分で閉じ、PR は issue にリンクする。一部だけ入った issue は開いたままにし、入ったものと残りを本文に書く。閉じる理由は、実際に起きたことに合わせる。
- 見つけた別の問題を issue にするかは、利用者の基準で決める。基準が無ければ、選べる形で示す。すべてを issue にすると、閉じる数より増える数が上回る。

開いている issue が減らないときは `dotagents:triage` のスキルを読む。

### PR

- PR の base はデフォルトブランチにする。
- PR を draft で開くリポジトリーでは、検証が済んでから ready にする。

### リリース

リリースするときは `dotagents:releases` のスキルを読む。
