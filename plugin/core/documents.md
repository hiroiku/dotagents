### 記録の置き場所

- issue は作業単位の記録にする。作業が終わっても続く事実は、文書に置く。
- 文書の置き場所は、事実の種類で決める。
  - エージェントの作業の手順(環境の準備、使うコマンド、作業の進め方、レビューで見ないもの)は、AGENTS.md に置く。AGENTS.md は README のエージェント版で、手順だけを書く。
  - 技術の選定、構成、配置、不変条件は、それぞれの理由と見直す条件を添えて `ARCHITECTURE.md` に置き、変えるコードと同じ PR で更新する。
  - 詳しい仕様(API、データの形)は、リポジトリーの docs に置き、コードと同じ PR で更新する。AGENTS.md と `ARCHITECTURE.md` からはリンクし、同じ事実を 2 か所に書かない。
  - 業務の決定、運用の手順、利用者向けのマニュアルは、Wiki に置く。Wiki が使えない環境では、`docs/wiki/` に Wiki と同じ形(1 ページを 1 つの Markdown ファイル、トップを `Home.md`)で置き、ほかの docs と同じく PR で更新する。
  - 業務の決定がコードの制約になるときは、理由を Wiki に、制約をコード(型、テスト)に置き、docs からは Wiki へリンクする。同じ事実を 2 か所に書かない。
- issue を閉じるときは、作業のあとも続く決定を上の置き場所へ移し、issue からリンクする。
- 文書には、作業の状態、予定、進み具合を書かない。事実が変わったら書き直し、経緯は issue に残す。
