### ブランチとマージ

開発はデフォルトブランチ 1 本にマージする。リリースは、デフォルトブランチのコミットに tag を付けて行う。リリースごとのブランチは作らない。リリース済みのバージョンの修正もデフォルトブランチにマージし、次のリリースに含める。共有ブランチは、デフォルトブランチ、main、master と `.agents/dotagents.jsonc` の `protected` に書いた名前で、push には確認が要る。

- 作業ブランチはデフォルトブランチから切り、マージ前に最新のデフォルトブランチへ rebase する。issue ごとのコミットを残してマージし、squash するときは、終えた issue すべての `Closes #番号` を本文に書く。
- マージして push したら、作業ブランチを消す。worktree を使ったときは、worktree も消す。その前に、作業ブランチの最後のコミットがマージ先に入り、マージ先が push 済みであることを調べる。squash でマージしたブランチは `git branch --merged` では見分けられない。
