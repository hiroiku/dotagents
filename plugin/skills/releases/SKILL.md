# 版を出す

版を切ること、出すこと、出さないと決めることは、外へ届く操作である。プロジェクトが任せると決めていなければ、利用者に確かめてから行う。

- 版を上げる場所(ファイルの版か、tag だけか)と、tag を付ける時期とブランチは、プロジェクトのリリースの決まりと、選んだ git の流れに従う。決まりが無ければ、ファイルの版を上げてコミットし、そのコミットに tag を付ける。
- 1 つのリポジトリーから複数の製品を別々に出すときは、版、tag、リリース、マイルストーンを製品ごとに扱う。
- 版を切る前に、版の段の検査(通しのテスト、E2E)を回す。
- 版の中身は、版を切ったときに統合先にあるもので決まる。切るときに、統合先に入っている後の版の issue をその版のマイルストーンへ移し、終わっていないものを次の版へ送る。
- 前の版は、同じ製品で最後に使う人へ届けた版、つまり GitHub のリリースがある版を指す。tag だけ付けて出さなかった版は数えない。出さなかった版を起点にすると、使う人がまだ受け取っていない変更が本文から落ちる。
- 版を出すたびに、その版の tag で GitHub のリリースを作る。名前は tag と同じにする。本文には、前の版から何が変わったかを、使う人にとっての変化として書く。コミット、ファイル、内部の識別子の名前は並べない。末尾に、前の版の tag との比較へのリンクを付ける。
- 何が入ったかは、前の版の tag から後のコミットで決める。マイルストーンは予定なので、本文の元にしない。
- 出さないと決まった版のマイルストーンは、中身を次の版へ移してから閉じる。tag は消さない。
- tag やリリースを workflow が作るリポジトリーでは、自分では作らずに、できたリリースの本文を直す。
