# 版を出す

- 1 つのリポジトリーから複数の製品を別々に出すときは、版、tag、リリース、マイルストーンを製品ごとに扱う。前の版は、同じ製品の 1 つ前の版を指す。
- 版を出すたびに、その版の tag で GitHub のリリースを作る。リリースの名前は tag と同じにする。
- 本文には、前の版から何が変わったかを、その版を使う人にとっての変化として書く。コミット、ファイル、内部の識別子の名前は並べない。末尾に、前の版の tag との比較へのリンクを付ける。
- 何が入ったかは、前の版の tag から後のコミットで決める。マイルストーンは予定なので、本文の元にしない。
- 前の版の tag から後のコミットで閉じた issue とマイルストーンを照らし合わせ、ずれた issue を付け直してから、その版のマイルストーンを閉じる。
- tag やリリースを workflow が作るリポジトリーでは、自分では作らずに、できたリリースの本文を直す。
